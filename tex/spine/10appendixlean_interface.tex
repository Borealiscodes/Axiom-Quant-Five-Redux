specification of AxiomQuant Five Redux and its Lean formalization. The purpose
of this interface is to define the structures, operators, predicates, and
verification obligations that Lean must implement and prove.

\subsection{Verification Obligations}

Lean must prove:

\paragraph{Smoothness}
\[
\texttt{theorem smooth\_E : Smooth E}
\]

\paragraph{Stability}
\[
\texttt{theorem stable\_E :
  ∀ x y, ∥E x - E y∥ ≤ C * ∥x - y∥}
\]

\paragraph{Reversibility}
\[
\texttt{theorem reversible\_E :
  ∀ x y, E x = E y → x = y}
\]

\paragraph{Monotonicity}
\[
\texttt{theorem monotone\_E :
  ∀ x y, x ≤ y → E x ≤ E y}
\]

\paragraph{Altitude Preservation}
\[
\texttt{theorem altitude\_preserved :
  AltitudeA3 x → AltitudeA9 (E x)}
\]

\paragraph{Domain Preservation}
\[
\texttt{theorem domain\_preserved :
  DomainD1 x → DomainD5 (E x)}
\]

\paragraph{Invariant Correctness}
\[
\texttt{theorem invariant\_correct :
  ∀ x, E x ∈ Kernel5}
\]

\subsection{Operator Role}

The Lean interface ensures that:

\begin{itemize}
    \item all operators have formal type signatures,
    \item all structures are formally defined,
    \item all altitude/domain semantics are encoded,
    \item all verification obligations are stated,
    \item the pipeline is formally expressible in Lean.
\end{itemize}

This completes the Lean interface specification.
